# موقع PANDA للمنتجات الرقمية

موقع بسيط لعرض المنتجات الرقمية (صورة، وصف، لينك تحميل)، مع لوحة تحكم أدمن محمية بتسجيل دخول.

## التشغيل محليًا

1. ثبّت الباكدجات:
   ```
   npm install
   ```

2. اعمل نسخة من ملف الإعدادات:
   ```
   cp .env.local.example .env.local
   ```

3. ولّد هاش الباسورد بتاع الأدمن:
   ```
   node scripts/hash-password.js "الباسورد اللي عايزه"
   ```
   وحط الناتج في `ADMIN_PASSWORD_HASH` جوه `.env.local` **زي ما هو من غير أي تعديل** (السكريبت بيطبع القيمة بعلامات `\$` بدل `$`، لإن Next.js بيتعامل مع `$` في ملفات env على إنها إشارة لمتغير تاني وبيقص الهاش لو اتكتب من غير الـ escape ده). وحدد `ADMIN_USERNAME` و `JWT_SECRET` (نص عشوائي طويل).

4. شغّل السيرفر:
   ```
   npm run dev
   ```

5. الموقع هيفتح على `http://localhost:3000`، ولوحة الأدمن على `http://localhost:3000/admin/login`.

## هيكل المشروع

- `data/products.json` — بيانات المنتجات (بيتحدث تلقائي من لوحة الأدمن، وممكن تعدله يدوي كمان).
- `pages/` — صفحات الموقع (الرئيسية، عن بيئة العمل، تفاصيل المنتج، الأدمن).
- `pages/api/` — نقاط الـ API (عرض المنتجات للعامة، وإدارة المنتجات وتسجيل الدخول للأدمن).
- `lib/` — دوال قراءة/كتابة المنتجات والتحقق من تسجيل الدخول.
- `middleware.js` — بيحمي صفحات وAPI الأدمن من أي حد مش مسجل دخول.
- `public/images/` — صور المنتجات (استبدل placeholder-1/2/3.svg بصور منتجاتك الحقيقية).

## الرفع لاستضافة

المشروع Next.js عادي، يشتغل على أي استضافة بتدعم Node.js (زي Vercel أو أي VPS). محتاج تحط متغيرات البيئة (`ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH`, `JWT_SECRET`) في إعدادات الاستضافة بدل ملف `.env.local`.

ملحوظة: بيانات المنتجات متخزنة في ملف JSON على السيرفر نفسه، فلو استضافتك بتشتغل بنظام serverless (زي Vercel) هتحتاج كل تعديل يتعمل بعد آخر نشر (deploy) عشان الملف يتحفظ صح، أو ابعتلي لو عايز تنقلها لقاعدة بيانات حقيقية بعدين.
